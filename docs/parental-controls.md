# Parental controls and Home app organization

Hold OK on an app tile to open its action menu: **Move**, **Hide from home screen**, **Protect/Remove PIN protection**, and **App information**. The first time the updated launcher opens, it shows one short hint about this gesture. Hold OK on the Settings pill to open **Settings**, with **Organize**, **Apps**, and **Parental controls**.

**Apps** is a compact list with one focusable row per application. It shows whether an app is **On home screen**, **Hidden**, or **Protected**. Press OK to open an app, or hold OK to manage it. Hidden apps remain in the library and can be returned to the home screen from their action menu. **Organize** lists the visible home shortcuts; select one and move it up or down. Visibility, shortcut order, and protection are saved in private app storage and survive restarts and app updates. User visibility choices are stored separately from the existing `hidden_apps` configuration, so existing config and launcher preferences are preserved.

Open **Parental controls** to create a 4–6 digit PIN with the on-screen number pad, then select the apps that should ask for it. Protected tiles show a lock, and the library reports protection separately from visibility. Opening a protected app from a tile, the library, a module card, or another launcher action asks for the PIN. Managing a protected app, including hiding it, moving it, changing its protection, or opening Android's app information, also asks for the PIN. The parental-control screen and PIN changes require authentication after setup.

The PIN is never saved as text. The launcher stores a random 16-byte salt and a 256-bit PBKDF2-HMAC-SHA-256 result (100,000 rounds) in its private files directory, compares results with `MessageDigest.isEqual`, and never logs PIN digits. Three consecutive failures start a 30-second lockout; further failures double the delay up to 30 minutes. Lockout state survives a Home restart. PIN input stays in the dialog and uses no keyboard or network service.

The launcher asks on every protected launch and keeps no unlocked-app session, so returning to Home requires the PIN again before opening that app. This is a launcher-level control, not an Android account or device restriction: another home app, Settings, Google Assistant, notifications, recents, or another app can still start a protected package outside this launcher. A protected app can also start other apps itself. Use Android's supervised-user or device-management controls if those paths must be blocked.
